# デプロイ編の資材

連載第2部「10日で学ぶ Django 本番デプロイ」で使うスクリプトと設定ファイルです。

```text
deploy/
  lib/            どの日でも使う共通部分（OS判定・ログ・冪等化の道具）
  day-11/         サーバーの初期設定
  day-12/         SSH 鍵と root ログインの制限
  ...
```

## 対応する環境

| キー | 対象 | パッケージ管理 | ファイアウォール |
| --- | --- | --- | --- |
| `ubuntu` | Ubuntu 24.04 LTS | apt | ufw |
| `rhel` | Oracle Linux 9/10 | dnf | firewalld |
| `alma` | AlmaLinux 9 / Rocky Linux 9 | dnf | firewalld |

RHEL 系（`rhel` と `alma`）は手順がほぼ同じです。
違うところだけを分けて書いています。

## 設計の約束

### 1. 何度実行しても同じ結果になる（冪等）

途中で失敗したら、直してもう一度流せる状態にします。
「1回目と2回目で結果が違う」スクリプトは、
失敗したときに何をやり直せばいいのか分からなくなります。

### 2. 変更する前に、変更しない実行ができる

```bash
sudo ./deploy/day-11/bootstrap.sh --dry-run
```

本番のサーバーに初めて流すものを、いきなり適用しません。

### 3. 既存の設定を上書きする前に控えを取る

書き換えるファイルは `.bak-YYYYmmdd-HHMMSS` を残します。
消してから気づくことが、実際に起きるためです。

### 4. 自分を締め出さない

ファイアウォールや SSH の設定は、**間違えると入れなくなります**。
そのため、危ない操作の前には必ず「今つながっている経路が残るか」を確認します。
確認できない場合は、実行せずに止めます。

## 使い方

サーバーへ転送してから実行します。

```bash
scp -r deploy/ サーバー:/tmp/kururucms-deploy/
```

```bash
ssh サーバー
```

```bash
sudo /tmp/kururucms-deploy/day-11/bootstrap.sh --dry-run
```

問題が無ければ `--dry-run` を外して実行します。
